@@H1@@2. Теоретические сведения
@@H2@@2.1. Навигация в Jetpack Compose
@@P@@Современные приложения Android, как правило, состоят из нескольких экранов, между которыми пользователь перемещается. Фреймворк Jetpack Navigation включает библиотеку навигации, подключаемый модуль Safe Args и инструменты для работы с глубокими ссылками и обратным стеком. Компонент Navigation Compose позволяет описывать навигацию декларативно, так же, как описывается пользовательский интерфейс.
@@P@@Основные понятия навигации:
@@BULLET@@host — элемент пользовательского интерфейса, содержащий текущий пункт назначения; при перемещении по приложению хост меняет пункты назначения;
@@BULLET@@graph — структура данных, описывающая все навигационные направления приложения и связи между ними;
@@BULLET@@controller (NavHostController) — объект, управляющий навигацией, глубокими ссылками и обратным стеком; создаётся функцией rememberNavController(), которая сохраняет стек при рекомпозиции;
@@BULLET@@destination — узел графа навигации, отображающий своё содержимое при переходе к нему;
@@BULLET@@route — уникальный строковый идентификатор маршрута, ведущего к пункту назначения.
@@P@@Перед реализацией навигации определяют перечень экранов и маршрутов и оформляют их в виде enum class (для простых приложений) или sealed class (когда маршруты несут данные). Граф навигации описывается в NavHost: в него передаются контроллер, стартовый маршрут (startDestination), модификатор и завершающая лямбда с вызовами composable(route) { ... }. Переход выполняется методом navController.navigate(route), при этом маршрут помещается в back stack, поэтому системная кнопка «Назад» возвращает пользователя на предыдущий экран.
@@P@@Для управления стеком применяются методы popBackStack() и popUpTo(). Параметр inclusive = false сохраняет указанный маршрут в стеке и делает его верхним (возврат на стартовый экран без возможности «назад»), а inclusive = true удаляет и сам маршрут (переход на предыдущий экран с возможностью вернуться ещё раз). Получить стартовый маршрут можно через navController.graph.findStartDestination().
@@P@@Чтобы поддержать принцип UDF (unidirectional data flow), состояние выносится в ViewModel: обработчики интерфейса вызывают методы ViewModel, а UI реагирует на изменение состояния. Для перехода между приложениями используется Intent ACTION_SEND и системный ShareSheet, который не является частью навигационного графа приложения.
@@H2@@2.2. Адаптивный интерфейс и классы размера окна
@@P@@С выходом Android 16 поддержка широкоформатных экранов стала требованием к публикации приложений в Play Market. Основные правила адаптивной разработки: не использовать фиксированных размеров; классифицировать доступное пространство окна на компактное, среднее и расширенное; использовать библиотеку Compose Material 3 Adaptive; применять рекомендованные шаблоны макетов.
@@P@@Библиотека WindowSizeClass (material3-window-size-class) автоматически вычисляет доступное приложению пространство и возвращает класс размера окна по ширине и по высоте:
@@BULLET@@Compact (COMPACT) — ширина менее 600 dp, типичный телефон в портретной ориентации;
@@BULLET@@Medium (MEDIUM) — ширина от 600 до 839 dp, телефон в альбомной ориентации, небольшой планшет, раскрытый складной телефон;
@@BULLET@@Expanded (EXPANDED) — ширина 840 dp и более, планшет и десктопные окна.
@@P@@Ширина и высота классифицируются отдельно; класс размера окна является динамическим и меняется при повороте устройства, изменении размера окна, переходе в режим разделённого экрана или складывании устройства. Поэтому макет должен перестраиваться в момент рекомпозиции.
@@P@@Рекомендованные адаптивные макеты:
@@BULLET@@List-detail — окно делится на список и панель деталей; на широких экранах обе панели видны одновременно, на компактных показывается либо список, либо детали (с BackHandler для возврата к списку);
@@BULLET@@Feed — сетка эквивалентных элементов контента на базе LazyVerticalGrid; на компактных экранах сетка вырождается в LazyColumn;
@@BULLET@@Supporting pane — основная область (около 70 % на широком экране) и вспомогательная панель (30 %), которая имеет смысл только вместе с основным контентом.
@@P@@Элементы навигации тоже выбираются по размеру окна: нижняя панель для компактных экранов, navigation rail для средних, постоянный navigation drawer для расширенных. Состояние (текущий экран, выбранный элемент, класс размера окна) рекомендуется поднимать вверх по дереву компонентов, чтобы соблюдать UDF и корректно обрабатывать системную кнопку «Назад» (BackHandler либо activity.finish() для широкоформатного режима).

@@H1@@5. Выводы
@@P@@В ходе лабораторной работы были изучены и практически применены основные механизмы навигации в Jetpack Compose. Реализованы граф навигации с четырьмя и пятью пунктами назначения, передача данных между экранами через ViewModel, сброс состояния заказа, системный ShareSheet и динамический AppBar с кнопкой «Назад». Написаны инструментальные тесты, проверяющие маршруты и работу кнопок навигации.
@@P@@При реализации адаптивного интерфейса были использованы классы размера окна, PermanentNavigationDrawer, NavigationRail и шаблон list-detail. Это позволило корректно использовать доступное экранное пространство на телефонах, складных устройствах и планшетах, а также правильно обрабатывать системную кнопку «Назад» в каждом режиме.
@@P@@Контрольные задания закрепили материал: приложение Lunch Tray получило полноценную навигацию, а приложение «Мой город» было спроектировано с нуля с чётким разделением слоёв данных и интерфейса, ViewModel и адаптивными макетами. Таким образом, цели лабораторной работы достигнуты.
